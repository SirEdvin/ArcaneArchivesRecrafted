# 0017 — Catalog-bound input consumption

Status: implemented under delegated behavior authority; runtime crafting remains pending.

Pinned upstream `80944ce45c6559243d8928cc4b305bf379388652`, `recipe/gct/GCTRecipeList.java:104-124,136-152` supports name-based lookup, overwrite and removal, and indexed recipe access. These methods expose recipe definitions separately from consumption; they do not provide a catalog-bound input commit. This is an added conservation boundary for the modern port, not evidence of a reproduced upstream exploit.

Decision: `GCTRecipeList.consumeIngredients(ResourceLocation, GemCutterInputHandler, BooleanSupplier)` resolves the current definition by name and delegates to 0016's guarded input commit. Its guard checks the exact current recipe object before and after each condition evaluation. Replacement/removal during matching or condition callbacks rejects deductions. A replacement present before the call is deliberately resolved and its current costs used; previews are not authority. Missing IDs return no result without invoking conditions; null arguments fail before mutation.

This affects all four targets. It changes no costs, outputs, assets, save/network formats or registered recipes. The caller must own both catalog and inventory on the server thread and supply live authoritative, side-effect-free conditions. Existing low-level recipe/handler entry points remain input-only; this method is not full crafting authorization. It returns consumed ingredients, not output or a delivery receipt. Callback effects are not rolled back. Removing and restoring the identical definition before a guard finishes is allowed: current definition identity, not catalog mutation history, is the contract. Unrelated catalog changes are allowed.

Alternatives: resolve once without a final identity check (stale definitions can consume); compare only names (replacement retains the name); invalidate for every catalog write (unrelated changes unnecessarily fail); introduce global lifecycle/version machinery (not needed for this owned-thread boundary). Delegated behavior authority covers this adaptation, not publication.

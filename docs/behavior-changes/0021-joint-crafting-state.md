## Matching-only routing input

`acceptRoutingInput` ports the input acceptance policy of pinned upstream `80944ce45c6559243d8928cc4b305bf379388652`, `tileentities/GemCuttersTableTileEntity.java`, method `acceptStack`: scan slots in ascending order, insert only into existing item/data matches, return the surplus without filling empty slots. This is deliberately separate from general stacked insertion. It delegates native capacity and insertion to the private input handler, preserves detached arguments/remainders, and rejects real/simulated callback reentry using the existing 0021 guard. Pending output is unaffected. Simulation reserves nothing; real insertion is incremental. The future runtime adapter must enforce routing access and mark actual changes dirty, rather than copying upstream's unconditional final dirty call (including simulation) into this runtime-independent owner.

Introduce a shared server-thread-confined `GemCutterCraftingState` that privately owns inputs and one pending result. Craft resolves the catalog and current conditions via the existing guarded bridge. Success retains the result before returning; a pending result blocks further crafts, including zero-cost crafts. Reentrant crafts, input writes, loads and saves during condition evaluation are rejected. The guard resets after exceptions. Conditions must still be authoritative and effect-free; arbitrary external callback effects cannot be rolled back.

Save inputs and pending result in one versioned compound; decode all fields into temporary owners before replacing either live field. Require an explicit byte pending flag (0/1), with a result compound exactly when set. Reject malformed records rather than restoring inputs without their pending result. Input reads are detached and no handler is exposed. The pending result is immutable with copied stack accessors; reading it is not delivery authorization.

All four targets, fresh-world format only; no legacy import, cross-version save conversion, packets, textures, costs or dependency changes. This is a new conservative internal state boundary, not a faithful copy of the old output handler. Alternatives rejected: separate unrelated save calls, overwrite existing pending result, unconditional clear/take without a delivery protocol, and public mutable input ownership.

# 0.0.2 Implementation Plan — Connected Storage and Tome of Arcana

**Status:** In progress — native device discovery/current Hive visibility implemented under [0131](../behavior-changes/0131-network-device-discovery.md). Manifest/Brazier/Tome implementation and release acceptance are not complete.

**Goal:** Deliver the original-style usable storage network alongside the complete Tome of Arcana on Minecraft 1.20.1 Fabric/Forge and 1.21.1 Fabric/NeoForge, preserving upstream behavior except for explicitly approved changes.

**Architecture:** Extend the existing shared Java/resource tree and four-leaf Stonecutter layout. Reuse native inventory/fluid adapters, persisted device ownership, Hive membership and Patchouli recipe components; isolate only actual loader/version differences. The Manifest locates stored items—it is not a remote-withdrawal terminal.

**Tech stack:** Existing Java 17/21, Gradle, Stonecutter, Fabric/Forge/NeoForge and external Patchouli dependencies. This plan does not authorize new tooling or dependencies.

**Execution:** Implement directly, without delegating coding. Deliver integrated gameplay groups rather than helper-by-helper handoffs. This document is a release implementation plan, not authorization to publish, commit, push, bump the version immediately, or change gameplay semantics.

## Scope and baseline

Read `AGENTS.md`, `docs/MIGRATION_TASKS.md`, `docs/HANDOFF.md` and the linked behavior records before implementation. Newer evidence supersedes historical missing-feature statements; an unchecked parent does not mean all of its implementation is absent.

Existing foundations to reuse:

- Radiant Chest/Trove/Tank local storage, automation, upgrades and portable paths.
- Radiant Crafting Table, Gem Cutter and quartz/Resonator acquisition progression.
- Storage scepters, Radiant Key/LOCK and Devouring Charm/VOID.
- Hive invitations, resignation, expulsion and persisted membership.
- Monitoring Crystal placement/target lookup and persisted device ownership.
- External Patchouli backend, player receipt persistence and Gem Cutter recipe-display adapter.

These foundations have differing verification coverage. Compilation and focused tests do not establish complete gameplay parity.

### Explicit boundaries

- Fresh worlds only; ordinary persistence of worlds created by this port remains required. No legacy-world import or cross-loader/version save conversion.
- Preserve reachable upstream behavior; do not activate dormant machinery or invent missing original abilities.
- Radiant Furnace and its accessor/Echo-production path remain excluded under 0110.
- Preserve the approved integration scope in 0113 and later decisions, including the existing KubeJS target exception and scripted-data exclusion.
- Unrelated Arsenal combat compatibility and unfinished upstream machines are not prerequisites for this storage milestone. Preserve complete in-scope Tome content and accurate feature gates; do not silently delete chapters to hide migration gaps.
- New behavioral deviations require a separate `docs/behavior-changes/` record and approval before implementation.

## Verification commands and evidence policy

Use the existing wrapper and test harnesses; inspect task/script arguments before selecting targeted commands. Do not invent a new testing framework. All Gradle commands, including targeted tasks, require an explicit timeout, `--no-daemon`, and complete silent file logging:

```sh
mkdir -p build
LOG="build/gradle-$(date +%Y%m%d-%H%M%S).log"
timeout --foreground 10m ./gradlew build --no-daemon >"$LOG" 2>&1
```

At integrated checkpoints run the existing artifact verifier with bounded execution and complete logging:

```sh
timeout --foreground 2m python3 scripts/verify_artifacts.py >build/0.0.2-artifacts.log 2>&1
```

These commands are planned checks, not results. Capture exit status immediately and measure duration; inspect only the relevant failure window. A passing build or operator-seeded world is not proof of connected gameplay. Keep runtime logs/build outputs untracked and visual evidence outside the repository.

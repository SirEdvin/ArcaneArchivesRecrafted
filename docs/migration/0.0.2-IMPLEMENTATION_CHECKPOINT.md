# 0.0.2 implementation checkpoint

## Status

The identified production Tome, Chest acquisition, Manifest hover shortcut and storage-preference gaps are implemented. The current four-target artifacts are ready for the user's initial gameplay test. This is **not release acceptance or a claim of complete upstream parity**. Graphical/connected/restart/integration campaigns remain deferred by the user's implementation-first direction. Earlier chronological notes in MIGRATION_TASKS/HANDOFF describe their historical checkpoints, not current missing features. No commit, push, tag or publication was performed.

## Implemented in this completion pass

- Full audited development Tome (`80944ce45c6559243d8928cc4b305bf379388652`): 98 source sections converted to 73 native Patchouli entries, 415 pages, 44 recipe displays and 25 illustrations. The 317 original targets are validated; anonymous continuations are grouped and only approved Radiant Furnace content is excluded. `scripts/port_tome.py` and `docs/migration/tome-conversion.json` make generation/reference coverage reproducible.
- Native Patchouli item, image and text components, conditional pages/entries, nested emphasis, navigation and live Gem Cutter output-selected recipes. Original unfinished topics remain explicitly identified as such, not invented gameplay instructions; unavailable legacy item references are labels rather than invalid stacks. Presentation adaptations: [0151](../behavior-changes/0151-complete-tome-patchouli-adaptation.md).
- Both original Radiant Chest recipes, modern wooden-Chest compatibility tag and native payment tests: [0152](../behavior-changes/0152-radiant-chest-crafting-restoration.md).
- Hovered-item Manifest tracking from container slots and optional JEI overlays/recipes/bookmarks. References are bounded, cloned and validated; the server resolves current authorized sources, throttles collection, grants no items and closes the current container only after accepted selection when Shift is not held. [0153](../behavior-changes/0153-manifest-hover-shortcut.md).
- `TrovesDispense` and `DefaultRoutingNoNewItems` in client.properties, synchronized as two authenticated-player booleans on connection/player replacement. No arbitrary player identity or world mutation is supplied by the packet. The original default `TrovesDispense=true` means ordinary click withdraws one and sneaking withdraws a native stack; false reverses it. This preserves the actual original code rather than its contradictory config comment.
- New Chest placement and quartz conversion honor the routing default, preserving explicit imported `routingType` and existing inventories. Native tests exercise the real four withdrawal combinations, packet round trips, explicit saved routing states and conversion conservation/payment. [0154](../behavior-changes/0154-storage-player-preferences.md).
- NeoForge custom GameTest compile-only dependencies now inherit main compile-only dependencies, complementing existing runtime inheritance.

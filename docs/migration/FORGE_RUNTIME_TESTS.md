# Forge loader-run verification

## Authorization and scope

The user approved repairing the Forge verification setup with native loader-run GameTests while retaining standalone JUnit and keeping test tooling out of release artifacts. This is test infrastructure, not a gameplay deviation. The broader migration and release acceptance remain incomplete.

The previous `build` failed in `GemCuttersTableCraftingTest.bootstrap`, before its test body, because plain JUnit did not apply Forge's `NetworkEvent` transformation. The failure could also leave vanilla bootstrap partially initialized for later test classes. Passing later fixtures was not proof of a correctly loaded Forge runtime.

## Implementation

- `build.forge.gradle.kts` configures a test-only `gameTest` source set and the native `forgegametestserveruserdev` launch through ModDevGradle 2.0.143. No Testiarium dependency or replacement loader is required.
- `src/forgeGameTest/java/com/aranaira/arcanearchives/gametest/ForgeRuntimeTests.java` launches the existing JUnit Jupiter fixtures on the real GameTest server thread, after Forge transformation, registration and world startup. Existing test bodies and assertions are unchanged.
- The source-set outputs of production, shared tests and the bridge belong to a single runtime mod model for this run only. Shared fixtures use production packages and package-private APIs; separate Java modules would cause split-package resolution failures. Normal client/server runs load only the production model.
- Test-only JUnit dependencies also enter this run's additional legacy runtime classpath, as required by Forge's library loading. The Jupiter engine is registered explicitly, and the context class loader is scoped to Forge's transformed loader with `finally` restoration.
- Discovery scans the compiled shared-test roots. Zero discovered tests, test/container failures, skipped or aborted tests fail the required GameTest and therefore Gradle. The legacy XML listener writes individual fixture results, not just the aggregate GameTest status.
- Ordinary `:1.20.1-forge:test` retains the seven standalone fixture classes (36 cases). The GameTest run executes all 178 active shared Forge cases, including those 36; these counts must not be summed as unique coverage.
- `check` depends on `runGameTestServer`, so root `build` cannot bypass the loader-run assertions. The test world, copied empty structure and XML reports live under the Forge leaf's ignored `build/` directory. No EULA file is generated by the build configuration.
- Release binary/source artifact checks reject the GameTest bridge, test classes and JUnit packages. Nothing is added to production dependencies or jars.

This does not automatically enable NeoForge-only test bodies on Forge. The native GameTest supplies a loaded runtime for existing assertions; those assertions are predominantly fixture-level tests, not connected-player gameplay, visual validation, or a save/restart campaign.

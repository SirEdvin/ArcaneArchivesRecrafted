# 0.0.3 — Presentation and storage limits

Gameplay-testing release prepared at the user's request. Supports Minecraft 1.20.1 Fabric/Forge and 1.21.1 Fabric/NeoForge. Patchouli remains required; EMI and JEI remain optional.

## Changes

- Radiant Chest counts use native decoration depth in front of item icons.
- Growing quartz is rendered above its Resonator using server-normalized progress, without changing production timing or creating early harvestable blocks.
- Radiant Crafting Tables display one model per occupied input slot, independent of stack size. Visual inventory updates are sent to nearby clients.
- Manifest **XMI integration** supports EMI first and JEI as fallback, retaining query copy/synchronization/restoration semantics.
- Independent per-player placement limits for Radiant Chests, Troves and Tanks, persisted across dimensions and unloaded chunks.
- Tome block presentations use native Patchouli block previews. Only Blocks, Items and Concepts categories remain; finished gem entries retain their IDs.
- Audited unfinished content is hidden from the Tome, creative tab and recipe viewers. Registry IDs, saved blocks and recipes are not deleted.
- Arcane Arsenal defaults on. Existing explicit opt-outs remain respected.
- Lectern-origin tracking stays anchored to the lectern. Tracking uses capped, solid 1/16-block beams.

## Configuration

### Brazier Pull mode

Use the Scepter of Manipulation to switch Deposit/Pull. Sneak-use the scepter for existing radius/network settings. In Pull, right-click with an item to select an exact filter without consuming it; sneak-right-click empty-handed to clear it. No filter means no pulling.

The one-stack output buffer pulls from permitted loaded Radiant Chests/Troves in range, up to one stack per second. Hoppers/pipes or empty-hand right-click retrieve output. Full buffers stop pulling. Switching modes/filter never deletes output; block removal drops it. Pull mode disables deposits and tossed-item collection.

### Placed-storage limits

In `config/arcanearchives/server.properties`:

- `RadiantChestLimit=64`
- `RadiantTroveLimit=64`
- `RadiantTankLimit=64`

Each setting applies per player across all dimensions. `0` means unlimited; negative values are invalid. Restart to apply changes. Creative bypasses placement enforcement but placements still count. Returning to survival never removes or disables existing storage; additional placement is denied while at/above the configured limit. Quartz chest conversion checks the same quota before moving items or consuming quartz.

`EnableArsenal=false` in `config/arcanearchives/arsenal.properties` remains an explicit opt-out.
